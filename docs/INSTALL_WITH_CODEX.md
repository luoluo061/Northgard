# 给协助安装和使用的 Codex

先读根目录 AGENTS.md 和 README.md。这里的命令只安装本地采集代码，不需要修改游戏，也没有后台上传服务。

## 1. 找到解释器和游戏

确认 Windows 64位、Python ≥3.11且解释器为64位。使用现有 Python/`py -3`；缺失时说明具体条件，用户选择安装来源。无需pip依赖、管理员权限、防护关闭或PowerShell执行策略更改。

将仓库克隆到普通工作目录，不覆盖现有仓库、游戏或captures。确认远程是用户指定的 `luoluo061/Northgard`，查看当前提交。私有仓库无访问权限时，请所有者邀请或使用用户已提供的合法源码包，不索取令牌文本。

运行 `python scripts/setup_local.py`。它从已注册Steam库定位Northgard；有多个安装或定位失败才需要 `--game-dir`。仅核验 `hlboot.dat` 和 `res.client.pak/data.cdb` 的哈希，并在采集器目录生成必要定义；不会运行这些游戏文件，也不会修改它们。

之后运行 `python scripts/doctor.py`。`ready_for_local_test`只代表本机准备完成，不代表读到了对局。版本不匹配时保留失败结果，等待维护者适配；禁止改profile哈希绕过检查。

## 2. 在用户自己的单人局短测

用户表示已经开好对局且授权采集后，使用新目录：

```powershell
python collector/collect.py --seconds 120 --interval 0.5 --out-dir captures/first-check
```

不要替用户开局或控制单位，除非他们另有明确指令。未在对局、进程关闭、读取竞争或不支持的氏族都必须如实报告。先验证基础数据，然后逐个检查labor和population_growth组件的status/缺失原因；程序启动或资源可读不代表全部组件可读。

至少核对：

1. 游戏时间推进；暂停时不以墙钟推生产。起点A800年3月，每60游戏秒一月。
2. 本人身份及session/run/segment正确；读档和重新连接会分段。
3. 粮木金库存和缓存产消可读、数值有限；Food分槽不等于总粮毛产。
4. 逐人任务、生产门控及加成输入能保存；未知最终率仍为null。
5. 指派→转职→生产候选恢复有时间区间；不要把总延迟称为纯走路。
6. 市政厅真实增长进度、幸福和阻塞输入是否能读；缺加成时不假设growthBonus=1。
7. 只导出自己单位、自有建筑与允许的已探索信息。

报告每个组件成功率、缺失字段和短测范围，不能把候选状态写成逐人实产。

## 3. 正式采集、停止、反馈

短测确认后，按用户安排省略`--seconds`采一整局。Ctrl+C或STOP可以停止。显式秒数是墙钟测试上限，游戏中的月份和所有劳动分析都使用游戏秒。

检查manifest的停止原因。`game_finished`表示读到游戏结束标志，`duration_limit`、`keyboard_interrupt`、`stop_file`均不能证明全局结束。保存错误/读取缺口，不跨段连接状态。

请用户按docs/PLAYER_FEEDBACK.md填写氏族、地图、经验水平、胜利目标、关键操作的年月/月段和原始游戏秒，以及自己认为值得验证的经验。将观察、解释和建议分开，允许“未知”。

## 4. 回传是独立动作

依docs/DATA_CONTRIBUTION.md生成本地审阅包，运行验证，展示将提交的文件、元数据与字段范围。只有人类用户已明确授权向指定仓库分享这一局，才执行该仓库的分支/PR提交。已有明确授权时按其范围继续，不重复请求例行确认。

不用邮件/聊天/其他云盘替代指定目标，不递归打包captures父目录，不上传research-raw、绝对路径、PID/内存指针、完整游戏定义或敌方全图。没有上游写权限时使用文档的fork/PR或由有权限的协作者提交；不改变仓库可见性，不在任何文件写入凭证。
