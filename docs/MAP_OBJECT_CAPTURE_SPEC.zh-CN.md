# 地块内容扩展：对象、读取契约与验收

状态：0.5.2之后的扩展规格与当前原生入口核验，不是已新增全部运行时采集的声明。现有运行时支持仍见[地块详情](KNOWN_ZONE_DETAILS.zh-CN.md)；整体目标和顺序见[项目路线](PROJECT_ROADMAP.zh-CN.md)。规则绑定现有受支持双指纹，未支持模式、动态规则和可见分支保留未知。

## 1. 覆盖对象，不能只覆盖图标

| 对象族 | 必须采的事实 | 还必须查的机制 |
|---|---|---|
| 动物、怪物、被动生物 | 原生类型、受支持可见数量、所属地块、玩家/中立归属分类 | 特殊显隐、是否敌对、战斗能力；普通熊与Kaija分开 |
| 巢穴与生成源 | 生成源UID/类型、当前状态；生成目标与参数另标配置 | 是否会继续生成、波次/触发条件；清掉生物不等于消除生成源 |
| 遗迹、沉船、废屋 | 地点UID、探索任务/进度、生命周期、可领取状态和原生事件 | 谁可探索、内容怎样计算、何时领取、是否需要殖民 |
| 氏族专属缓存 | 类型、创建者/可知资格、状态和进度 | 氏族限制、专属收益，不与通用遗迹混合 |
| 声望机会 | 地点或事件来源、触发、接收方、次数、原始状态 | 是否已满足资格/已领取、模式/科技修正；不能按地名给固定声望 |
| 中立势力 | 当前可知势力身份、已知占地、可见部队、本人与其关系/贸易/战争输入 | 相遇、通行、可交易/结盟/占领资格、独占奖励与收益接收方 |
| 特殊地块/目标 | 对象与附加属性、任务/占领进度、能力状态 | 一次性/持续/胜利条件、代价与适用域 |

“全部”的目录分母与实际采集覆盖分别保存。当前PAK中unit、building的全量行还包含普通玩家单位/建筑、氏族对象、战役、事件和特殊模式；这些行不能一起成为运行时白名单。

## 2. 中立身份入口

当前原生结构中，Unit.owner指向普通玩家，Unit.neutralOwner指向NeutralFaction，另有neutralOrigin记录来源。GameState.neutrals保存本局中立势力集合。新增适配器应先排除普通玩家对象，再要求中立引用的精确指针属于当前集合，并核实际类型、game/state和读前后稳定；不能以kind名字或owner是否为空猜身份。

已探索Zone.owner若被验证为该本局中立势力，可以作为中立占地与已相遇证据。普通hasMetFaction路径检查中立占地与本人已探索集合的交集；RelationData.seen分支不能机械地当作所有中立势力的必要条件。Outsiders和若干特殊势力有例外，不混入普通营地规则。

本人外交候选入口为me.relations中的势力引用及common关系状态。alignment、trade、warUntil可以先记录为原始输入；关系阶段、通行与合法行动仍需按势力/规则解释，不能直接floor(alignment)作为通用阶段。只读本人的相关关系和玩家可知中立状态，不递归读取其他对战玩家的库存或经济。

本版本neutral表有9类：GiantFaction、KoboldFaction、MyrkalfarFaction、LightalfarFaction、DwarfFaction、GayantFaction、MarmennillFaction、OutsidersFaction、KoboldKingFaction。这里是配置目录；不表示九类都出现在普通地图、都拥有可殖民营地或都支持相同外交行动。

## 3. 地点状态不能套一种解释

Building共用state代理包含active、activeDate、contains、nextWaveTime、progress、spawnMax、spawnWavesProgress、stock、waveIsInProgress等可空字段。这些只是候选原生输入，不给所有地点相同含义，也不把字段缺失填0。

已核探索内容分支使用Ruins、BrokenShores、BrokenHouse。Wreck这个名字不能直接证明它是本局活跃沉船；未核用途的配置条目保留catalog_only。探索任务推进progress后，在完成路径上取内容、将state设为null、发放资源并写Explore事件。因此：

- progress应按具体地点解码，不能用普通矿的含义解释所有contains/progress。
- Ruins.state=null可能是正常生命周期结果，不是通用读取错误；也不能仅凭null断言“本玩家刚刚领取”。
- 开始探索、完成、领取及领取者分别建立证据；有任务前后和原生日志时再连接成事件链。
- 内容计算包含氏族/额外收益等分支，配置参考金额不能冒充最终报价或实付。

Treasure/CursedTreasure涉及当前鹰族缓存配置，必须单独处理资格。自然地点的kind、运行时派生类和别名要同时核验，不能重复此前仅凭CircleStone名称猜类的错误。

普通熊族与鹰族的探索资格已核出一个实际差异：Ruins/BrokenShores/BrokenHouse的默认assign.flags为0，Eagle氏族覆盖为10，包含AnyOwner与NoHostility。HBuilding.hasAssignFlag（#16679）取氏族覆盖；Building.getNoAssignReason（#5812）检查所有权，Ruins.getNoAssignReason（#21739）不豁免所有权拒绝。因此普通熊族的默认路径需先取得土地；鹰族可有领土外指派资格，但仍需通过敌意、路径和耗用等门槛。此结论不自动扩到战役、其它规则和所有单位。

当前静态入口可作为第一批适配的核查索引：

| 类型/入口 | 已核配置或调用 | 运行时还要补什么 |
|---|---|---|
| WolvesCave / DeathCamp / SpiderDen / Foxhole | 分别关联Wolf / Death / Spider / Fox；当前尸鬼底层ID为Death | 当前生成源、实际生物、状态与生成时钟；配置上限不当现存数量 |
| Ruins / BrokenShores / BrokenHouse | 探索内容与完成路径；#37116内取内容、state清空、发放资源 | 完整资格、任务前后、实际领取者与到账；默认配置不当最终奖励 |
| FountainFame | Mimirsbrunn知识用途；不能按名字归入声望 | 工作进度、选择/完成状态与有效条件；配置目标不当每秒率 |
| Geyser / AncientGraveyard / FountainHealth | 已识别地点与静态values线索 | 每类状态、作用域、有效资格和数值语义 |
| ThorWrath / WyvernDen / Yggdrasil等 | 配置有生成源、候选奖励或目标；三者机制不相同 | 清理/控制/持续或目标触发、接收方、实际收益；逐模式核验 |
| Zone.fameState / takeControl #5944 | 原始状态与控制权奖励路径 | 可领取资格、状态枚举和发放事件，不能把整数直接命名claimed |

表内没有新增运行时许可；特殊地点仍逐项核具体类和显示规则。目录仅投影选定values字段，并标出动态定义/升级覆盖是否存在；未投影的字段和表达式不等于原配置中不存在，静态val也不是最终有效量。gen.createdBy记录生成关联线索，不证明本局已生成该对象。

## 4. 声望来源与领取必须拆开

声望参考至少区分：发现、击杀/清理、探索/领取、取得控制、持续持有、任务及中立关系。具体某类是否支持某个触发，需按当前代码建立映射，不能把这个分类表当作每个对象都有的奖励。

Zone.fameState是可读取的原始整数。界面奖励路径将其与canWinResOnTakeControl、中立势力的eradicationReward、资源资格和科技组合；单个整数不足以解释所有地方的“已领/未领”。首批可以保留fame_state_raw及语义状态，不能擅自把3改名通用claimed。

每条收益记录至少分四层：配置奖励候选、当前资格/报价、观察到的触发事件、实际本人资源变化。前两层不能自动生成后两层，也不能重复把同一次资源发放计为清野、殖民和探索三份收益。负声望也要保留，不能用非负过滤器丢弃。

本人声望点与解锁等级也要分开。当前六资源公共库存尚未包括Fame；既有`fame_level`来自`me.tech.fameLevel`。点数的已核原生入口为`me.res.resources.map['Fame']`（Player.res字段104→ResourcesComponent.resources字段35→MapData.map字段4）；`Player.getResource #4713`转调`Resources.getResource #13480`，特殊资格和战役分支可能改变有效返回。后续在普通受支持上下文中加入原始点数和缺项原因，不能执行getter、把缺键补0或由等级推点数。点数变化与`addFame`触发、一次性奖励及氏族门槛分别连接，不能只把配置奖励相加当当前余额。

FountainFame在当前配置中关联Mimirsbrunn的知识用途，不能按ID含Fame直接认作声望泉。中立礼物和消灭奖励也各有接收方/资格，矮人的负声望项说明“打掉中立一定赚钱”不是可用规则。

## 5. 建议的观察结构

以下是待实现的扩展契约，不是0.5.2现有字段：

- 对象身份：session/run/segment、zone_id、object_uid、kind、受审运行时类、对象族。
- 可知依据：已探索集合来源、显示规则分支、是否支持当前显隐、观察的游戏时间区间。
- 状态：native_state_present与读取结果分开；按类型定义raw字段及语义，null原因区分正常生命周期、未物化、读错和不适用。
- 中立归属：本人/本局中立/未归属/未支持；只导出经过约束的势力类型，不导出原始指针。
- 收益候选：触发、资源向量、次数/接收方、条件与来源；动态资格未求值时标unknown。
- 动作证据：任务开始/进度、完成、取得控制、关系变化与领取事件，各自附采样区间。
- 覆盖：目录是否有该类、字段已实现哪些、可见规则是否支持、离线与实局验证分别记录。

对象消失只先记not_observed；没有数组、读取失败、对象被移除、换局不能直接叫死亡、清完或领完。所有连接只在同一来源身份内进行，不用后来地图补过去。

## 6. 实施批次与验收

| 批次 | 代码输出 | 验收场景 |
|---|---|---|
| A：常见中立与生成源 | 逐类型生物计数、巢穴对象与状态；玩家与中立owner分流 | 发现→清野→仍有巢穴/波次→殖民，草丛/特殊类未知，己方单位不算野怪 |
| B：常见探索地点 | Ruins/BrokenShores/BrokenHouse的UID、任务进度、完成/领取证据 | 未满足殖民/探索资格时拒绝或未知；已核氏族/规则例外单测；任务中断/恢复、正常null生命周期、额外收益、暂停和换局 |
| C：声望与特殊能力 | 本人声望点、fameState原值、逐触发奖励资格与实际结算关联 | 等级与点数不同、同地不同动作、奖励已被别人拿走、负收益、科技/氏族改变资格、重复事件去重 |
| D：中立外交 | 已遇见势力/已知占地、本人关系原值、交易/通行/结盟状态 | 初遇前后、非玩家owner、不同势力阶段、独占奖励/特殊势力不混普通规则 |

每批都要完成：类型与版本核验→只读适配→失败隔离→严格投影/贡献校验→正反例→玩家正常对局短测。完成A不等于B–D已采齐；目录工具不替代任何一批的运行时验收。

生成旗标gen.flags属于地形/生成约束，preCache属于预载线索；它们不能单独证明条目仅属某模式。模式资格未知时保留not_evaluated。
