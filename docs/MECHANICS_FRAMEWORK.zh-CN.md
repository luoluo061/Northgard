# 用人口与时间重建Northgard的机制模型

研究目标是：**在当前状态、氏族、已学知识与期限下，怎样安排人口和投资，能更快实现明确目标并维持经济。**库存、人多、某个岗位毛产高，都只是决策的一部分。

当前应按“版本规则 → 状态变量 → 行动转换 → 小实验 → 对账 → 策略比较”的顺序推进。采集器承担状态与事件证据；计算模型解释规则；策略层比较有前提的方案。三者分别保留未知，避免从一条库存曲线直接跳到最优建议。

底层需要同时理解三份材料：`data.cdb`给基础参数与引用；`hlboot.dat`中的HashLink编译逻辑决定何时使用、替换和组合参数；`GameState/Player/Unit`提供这一刻的状态。资格判断、产消汇总、库存结算和UI格式化是不同环节。外部模型重建数学函数，再用原生汇总率和库存对账；完整输入尚未齐全的分支返回未知。

## 1. 状态必须足以解释同一个人在做什么

| 状态 | 为什么需要 |
|---|---|
| 游戏时间、季节、天气与模式 | 资源积分、冬罚、取暖、事件及规则分支 |
| 住房人口P、食耗资格与倍数、取暖名单 | 三个口径不同，不能统一拿单位对象数替代 |
| 每人职业、当前任务、生产资格、位置、指派、状态效果 | 同样叫村民，可能在采食、施工、走向目标或参战 |
| 粮木金石铁知识的库存及原生产消 | 连续流量与一次性支付分别处理 |
| 幸福H、住房上限、市政厅进度及出生条件 | 解释未来可用劳力，而不只看当前人口 |
| 建筑、升级、施工进度、岗位容量与维护 | 建好、有人到岗和真正投产有时间差 |
| 本人已知地块、归属、邻接、资源点与剩余量 | 决定哪些行动可行；缺失资源点和通路保持未知 |
| 氏族、知识树、已学知识、工具、临时效果 | 决定计算分支、合法行动和资源转化方式 |
| 军队、战团容量、声望、目标与期限 | 让经济有明确用途，而非无限囤资源 |

单位UID连接的是同一个实体；职业不是工资条。`produce`标签或建筑指派也不能独立证明已经入库。原生字段名同样要核语义：储存的`population`字段不能普遍当住房人口，市政厅进度不能由资源组件里同名增长槽替代。

## 2. 一个普通人：先建立可计算的基线

本节绑定`v4.3.29.43387 / Steam Build 25096976`。只讨论普通人类经济、无其他加减成、持续有效工作、固定人口、无封顶与饥饿积分效应的条件模型；不是所有氏族的统一公式。证据与函数索引见[rules.v1.json](../mechanics/rules.v1.json)。

每游戏月60游戏秒、每游戏年720游戏秒，零时为A800年3月。普通UI收支通常先将原始每秒率乘10再舍入；调试分支另有规则。所有计算统一用资源／游戏秒，不把屏幕的`+4`当成每秒4。

健康、无修正的村民有效采食毛产为：

```text
g = 0.4 粮 / 游戏秒 = 24 粮 / 游戏月
```

食物消费要分人口规模项和逐单位资格：

```text
b(P) = 0.1 × (1 + sqrt(P / 46))
普通成员食耗小计 = b(P) × Σ[各单位的食耗倍数]
```

外层还有难度、消费系数、特殊模式、出口与其他独立项。只有所有人均为食耗倍数1的普通成员、且外层系数均为1时，才能简化为：

```text
C(P) = 0.1 × P × (1 + sqrt(P / 46))
净粮率 = 有效采食人数 × 0.4 − C(P)
```

例如固定10名普通人：全体每月食耗约87.975粮；4人采食毛产96，净余约8.025。此时6人可暂做非粮工作，但殖民、盛宴、备冬还需要额外粮食预算。

“一人养几人”应在指定P下解释：P=10时单人食耗约0.146625／秒，一个采食者扣除自身食耗后，约能供养另外1.728个同质普通工人。这是固定人口下的劳力等价数，不能按这个比例无限增加人口。

两种人口决策要分开：

- **现有人调岗：**普通等食耗岗位间转换，双方共同的食耗抵消；采食转施工首先损失原来的粮食毛产。不要在机会成本里再扣一次同一个人的基础食耗。
- **新增人口：**应比较`C(P+1)−C(P)`；人口规模上升会同时抬高已有成员的食耗。再加入住房、幸福、出生等待和未来可用人秒。

## 3. 冬季与氏族会改变分工

对已核的普通村民Food冬罚分支：

```text
f(P) = max(0.6, 0.7 − P/300)
普通冬季g = 0.4 × f(P)
熊族冬季g = 0.4 × [1 + 0.7 × (f(P) − 1)]
```

熊的0.7作用于冬罚幅度。普通与熊族的计算分支不同；鱼不套这段Food冬罚，农民冬季Wheat基础又先替换为村民值。其他加成要回到合并位置核算。

固定10名普通人、难度与其他消费因子均为1：

| 场景 | 每名采食者月毛粮 | 全体月食耗 | 稳态净粮不负的最少纯采食人数 |
|---|---:|---:|---:|
| 非冬季、无修正 | 24 | 87.975 | 4 |
| 普通冬季基线 | 16 | 87.975 | 6 |
| 熊族冬季、无冬节 | 18.4 | 87.975 | 5 |
| 熊族冬季、冬节生效 | 18.4 | 61.583 | 4 |

这只是食物稳态约束：没有备粮、贸易、事件和其他劳力收入，也没有增长人口。不能把“最少几人采食”直接当成一套开局建议。熊冬节的食物优惠在消费侧；非食物生产增益是另一条规则，不能重复计到粮食上。

生产修正常在同一个modifier里相加。已核普通路径按基础值、bonus与malus delta合并，再钳位；受伤和不幸福在特定分支里共用减益判断。不能把所有描述的百分比串乘，也不能只用当前血量替代持续状态效果。

## 4. 各类资源通过哪些通道产生价值

| 对象 | 主要转换通道 | 决策中应计算什么 |
|---|---|---|
| 食物 | 维持人口、殖民、盛宴、招募／氏族技能 | 储备、连续食耗、一次性预算与冬季安全余量 |
| 木材 | 生产建筑、住房、军事建筑、取暖 | 材料、施工占人、维护、投产延迟和何时解除瓶颈 |
| 钱 | 维护、贸易、招兵、部分氏族扩张与技能 | 税流／水手商人、现金期限、维护与合法支付路径 |
| 石头 | 建筑升级等有限资本投资 | 有限矿藏、矿工时间、升级带来的产能／岗位与回收期限 |
| 铁 | 工具、英雄／军备、部分技能 | 开采、锻造占人、所需前置与军事时间点 |
| 知识 | 达阈值后学习具体知识 | 提前多久解锁、影响哪些人、持续多久、替代了哪些劳动 |
| 幸福 | 出生速度、低幸福状态等 | 总幸福组成、住房与出生门控、未来可用劳力；不是可花费库存 |
| 人口 | 未来劳动／军事时间 | 新增全体食耗、幸福和住房成本，以及距目标还剩多少工作时间 |
| 土地／建筑槽位 | 可选资源、通路、岗位和战略位置 | 探索、合法性、威胁、支付、施工、人员到位的完整链 |
| 声望与军事能力 | 氏族奖励、解锁和胜利路径 | 触发门槛、取得时点、对未来规则和对局目标的影响 |

作为配置基线，普通木工q=0.4、农民夏季Wheat q=0.5、符文师Lore q=0.3；这些值仍需要生产资格和动态修正。矿工q是共享矿藏进度的输入，跨阈值离散到账，不能把小数进度当成当月必然拿到的石铁。

幸福与住房是劳动力供给系统。已核熊／乌鸦普通单人FreeForAll增长路径在H>0时以`sqrt(H)×growthBonus`增加市政厅进度，招募门槛为`55+5P`，不推广到其他氏族或模式。人口封顶、增长禁用、出生位置／战斗等门控另算。只有这些条件和未来率都固定，才能用`(门槛−当前进度)/增长率`作条件ETA。

## 5. 给“有效转换”一个可检验的定义

先声明目标，例如“在指定月份具备一支军队且维持过冬预算”“某日前让新矿投入工作”“提前学到某项经济知识”。随后比较同一起点的行动路径：

```text
Δ资源向量(T) = −额外一次性费用
              + ∫[方案的产出−基准方案产出−额外消费]dt
              + 额外事件收入−额外溢出
```

路径中包含移动、施工、转岗与到岗后的有效工作，因此不能又把同一段机会成本重复扣一次。所有资源保留各自单位；只有在明确目标和约束下才引入临时的边际价值，不设永久“1木=几粮”“1知识=几粮”。

例如无修正夏季，两人从基础村民采食转为有效农田岗位，毛粮从每月48变为60，稳态新增量是12，不是60。施工期间少掉的原岗产出、建筑材料与维护还未扣；进入冬季又要重算岗位基础。模型应比较这条完整路径，而不只比较农田的总产量。

有效性至少检查：行动是否可行、何时受益、目标是否更早达成、是否导致饥饿／现金断档、是否挤掉更急的住房／军备、是否依赖尚未知的地块或事件。收益高但赶不上期限的投资，价值会与长线局不同。

应优先输出资源向量、到达目标时间、关键瓶颈和不确定区间。完整目标尚未给定时，保留可比较的方案，不武断给唯一最优岗位。

## 6. 氏族层需要改变规则和行动图

氏族差异至少覆盖：开局单位与资源、人口／消费资格、生产与冬罚、合法支付资源、建筑和岗位、知识图、声望门槛、专属资源／技能和胜利路径。只给普通人产量乘一个“氏族系数”无法表达这些差异。

本机已核例子：熊族冬罚；熊族常规200声望奖励KindredSpirit生效且满足地块条件时，由盾兵营或同队熊／英雄分支触发，当前系数1.15，来源不能重复叠加。它虽在tech表中表示，也不等于普通知识树手点科技。乌鸦港口金币基础与普通港口不同；金币殖民必须先通过合法支付分支，它不是永久粮金兑换。细节见[证据目录](MECHANICS_EVIDENCE.md)。

科技采用有向图：节点要有前置、费用口径、合法获得方式、触发条件、作用对象、叠加位置与失效条件。“能点某知识”与“这一局已经生效”分别记录。历史更新公告会反转旧机制，不能仅凭知识名字或旧中文注释实现。

## 7. 信息收集和解码顺序

1. 核验本机hlboot/data.cdb双指纹，保留版本；解析配置、类型与编译函数。编译元数据不等于已获得原始源码。
2. 每条规则写出输入、输出、单位、分支、常量、前提、证据位置与未知。分别标成配置事实、代码推导、真实观察、控制实验通过或假设。
3. 从已有本人采集状态构造模型输入。生产资格或效果不完整时降为条件模型／区间，不把未知补0。人口使用已核住房口径，不用通用存储字段代替。
4. 在玩家授权的单人小实验中一次只改一个因素，比较模型、原生汇总率和库存结算。暂停、费用、模式、身份段和读取竞争全部保留。
5. 先闭合普通食物与人口，再做木材／取暖、建造、矿与知识、增长、熊／乌鸦，最后逐氏族扩展。每个模块有独立覆盖与反例，不以一个综合“已完成”覆盖未知。

官方编辑器及脚本可为隔离的自定义实验提供帮助；修改过规则的地图与普通对局必须分开标记。当前工作不执行游戏getter、不注入或操作游戏，也没有启动新一局采集。

## 8. 当前可运行的最小部分

`mechanics/baseline.py`实现本页同质食物算例，输出始终为`model_estimate`，不进入原生采集字段。它不检查当前局内是否满足前提，不模拟完整加成、出生、建筑或策略；不支持的氏族和模式拒绝。

下一步的验收单位应是“一条有前提的规则和对应实验”，而非新增了多少JSON字段。具体实验与通过条件见[MECHANICS_VALIDATION_PLAN.md](MECHANICS_VALIDATION_PLAN.md)。
