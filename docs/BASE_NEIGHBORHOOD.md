# 基地一环、二环与人口投入

0.5.0-alpha 在 `player-observations.ndjson` 的每个有效本人观察中增加 `base_neighborhood`。它从现有白名单地图派生，不增加对隐藏地图或其他玩家经济的读取。新版实局验证状态见 [VALIDATION_STATUS.md](VALIDATION_STATUS.md)。

要解释的是：这个月新增的一块地，付出了多少资源、施工和调岗等待，随后让哪些人口获得了新的工作机会。环数只是空间上下文，不能独立证明殖民优先级。

## 怎样划分基地和环

基地参照来自采集期间**首次唯一确认的、已完成的本方 `TownHall`**。记录它的地块和首次观察游戏秒。同一个 session 内参照固定，殖民新地、失去市政厅或在别处重建都不自动挪动基地。新 session 或本地玩家身份变化会重置。

中途加入采集不一定能看到原始出生点，所以 `original_spawn_status` 始终是 `unverified`。首次看到多个已完成本方市政厅时不任选一个。如果没有可靠基地，环层保持 `unknown`。

| 分类 | 含义 |
|---|---|
| `ring0_zone_ids` | 本帧已知地图中的基地参照地块 |
| `ring1_zone_ids` | 在本帧已知双向几何图中，与基地相邻的地块 |
| `ring2_zone_ids` | 在同一图中最短路径为两条边的地块，排除基地和一环 |
| `known_unclassified_zone_ids` | 本帧地图中已知，但无法确认在基地两环内的地块 |

一环不是坐标圆，二环也不是“看起来远一点”。使用 `map_observation.known_zones[].known_geometric_neighbor_ids`；只有两端都已知、且双方都列出的合法边才参与计算。重复、错误和单向边会留下原因。`witness_path_zone_ids` 保存基地到每个已分类地块的证据路径。

`observed_graph_distance` 是当前已知图中的距离，**不是完整隐藏地图的距离证明**。未分类不能直接叫三环或更远：未探索的通路或被拒绝的边可能改变分类。几何相邻也不证明单位当前能通过，地形、悬崖、阻挡和清地条件没有因此完成验证。

## 每块地能连接什么

`zones` 包含当前白名单地图中所有已知地块，含未分类项。以下字段都来自本帧，历史地图不会填充读取错误：

| 字段／连接 | 含义和限制 |
|---|---|
| `zone_id` | 当前视角、当前 session 的地块标识，不能直接跨电脑合并 |
| `exploration: known` | 已在本人的已知地图；多人可能来自共享视野，不证明本人侦察员刚开图 |
| `current_visibility: unverified` | 已知不等于当前可见 |
| `ownership: self / unknown` | 本人拥有可以确认；其他情况不猜无人、友方或敌方 |
| `own_unit_uids` | 本帧位于此地的本方单位，按 UID 连接 `units`；不是岗位人数或实产人数 |
| `own_building_uids` | 本帧该地的本方建筑列表引用，连接 `buildings`；其中可能含自然对象和装饰物 |
| 两项 `*_observed_game_time_seconds` | 分别保存地图与本方实体的观察游戏秒，保留非原子采样时间差 |
| `map_observation.known_zones` | 通过 id 连接地形类别、坐标、层高、湖泊标志及已知邻接 |
| `tiles`、`buildings` | 本方地块建筑槽位、施工目标／进度、指派单位等已采字段 |
| `operations`、`actions` | 按地块及所属 session/run/segment 连接本人殖民状态、付款记录、开工与完成证据；不可凭库存差直接猜一次支付 |
| `labor`、`labor_transitions` | 连接单位输入、指派和转职阶段；候选与阶段不证明逐人资源已到账 |

环层本身不把非本方地块的动态数组当作静态资源点清单。新增的独立[已知地块详情组件](KNOWN_ZONE_DETAILS.zh-CN.md)在普通单人FreeForAll中按本局已探索范围、自然资源白名单及可见性分支读取资源、石铁余量和限定狼熊，再通过`zone_id`与环层连接。该组件未完成真实短段验收，草丛和特殊分支保留覆盖缺口；其`partial`状态不能升级环层为全图完整，也不能证明通路、敌军或全部殖民条件。多人仍不支持该详情组件。没有字段不等于没有资源。

在已核版本中，`CellKind` 只有 `Default/Water/Coast`；`Cell.elements` 可在运行时增删，不能因名字像地图元素就视为不可变资源表。`Zone.hasNaturalFoodSource` 和 `hasFish` 又依赖建筑及动态状态。这是本版没有进一步补出非本方资源标记的依据，不代表游戏本身没有这些信息。

同一个 UID 必须在本帧本方单位／建筑中可验证才会作为引用输出。基地市政厅失去后，固定地块参照可以保留，但 `town_hall_uid` 变为 `null`，不会把历史建筑伪装成本帧仍存在。如果基地地块在当前地图中也不可验证，输出锚点地块为 `null`，不拿历史图来分环。

单位的 `zone_id` 为 `null` 时，不会出现在任何地块的单位引用中；这不等于单位消失或闲置。看该地多少人在工作，仍需联合岗位、指派、任务与门控字段判断。

## 按游戏时间做复盘

以 `game_time_seconds` 为准：0 秒为 A800 年 3 月，每月 60 秒；月初／月中／月末各 20 秒只是展示分组。

1. 在每个年月段列出**本次首次观察到的**一环、二环地块及其证据时间；首帧已有的信息不能说成刚被侦察发现。
2. 标出这些地块何时归属本人，何时出现施工、建筑完成和派工。已有地块的殖民标志变化不能重复计作新殖民或退款。
3. 按同一单位 UID 比较原岗位、施工／移动／转职阶段与新岗位。人在地块上和指派给建筑的人数分别统计；不要用实体数替代住房人口。
4. 把人口变化、科技／工具／冬季等输入、容量和一次性支付，与全局产消缓存及库存变化并列。观察到同时发生只能称关联；未知逐人实产仍是 `null`。
5. 给结论附覆盖和缺口。读错误、长间隔、回退或跨段之后重新建立观察基线，不跨缺口累计人秒；暂停不会增加劳动、产出或增长时间。

举例：A800 年 5 月中观察到二环新殖民地出现伐木场施工，月末两人转成木工。可以说“这次扩张连接到两名木工和施工占人”；还不能据此说“比殖民另一块地多赚多少木”，因为另一方案、路径条件、资源点、完整加成和逐人实际入库并未全部测得。

## 怎样判断采集是否成功

有可用基地和地图时状态为 `partial`：可检查已知两环，但完整覆盖始终 `incomplete`。缺少基地或地图时是 `unknown`。空数组表示本帧尚无可用证据，不能表示这一环不存在。`reason_codes`、`unknown_fields` 和 `continuity` 要随数据保留。

健康流新增 `base_neighborhood_status`，`component_diagnostics.base_neighborhood.source_status` 为 `derived`，表示从白名单数据派生。最终本地 manifest 的 `last_base_neighborhood` 只提供最后一帧数量摘要，不能作为整局覆盖率。当前贡献导出不含这项本地摘要，逐帧组件会按严格协议验证。

贡献验证器会独立重算环层、证据路径、当前本方引用与固定基地历史，拒绝未知地块引用和身份／时间错配。验证通过只能说明内部一致性，不能证明来源真实、实际可通行、隐藏地块完整或新版实局已验收。历史版本没有的新字段不回填成真实旧采集。

兼容旧流时，若前段没有可选的环层组件，验证器只能从首次提供该组件的观察建立锚点；不能借此声称已经验证更早的采集器历史或原始出生点。
