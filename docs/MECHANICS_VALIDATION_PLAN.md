# 机制实验：先做小而可反驳的检验

状态：设计，尚未执行本轮控制实验。所有实局由玩家操作；本计划不授权自动开局、调岗、修改地图、调用getter或上传。采用当前双指纹版本，按游戏秒记录，先保留无事件、无升级、无出生、同身份的有效窗口，再扩展条件。

## 共同记录与判定

每次保留氏族、模式、难度、游戏时间／季节、人口与住房、幸福与增长、知识工具、相关单位任务／状态、地块／建筑效果、生产与消费汇总、库存、付款／事件和读取质量。

尽量从同一状态分支，一次只改一个因素。移动／接单／转职过渡与稳态分别分析。保持相同的建筑维护和人口，避免把建造费、出生、贸易、探索奖励、封顶／触底或季节跨界混进岗位产出。至少重复数次并留未用于拟合的窗口复核；误差阈值由采样跨度、计数器精度、UI取整与离散事件决定，不凭一次吻合判全模型通过。

代码已核60游戏秒/月、720/年及普通UI格式化路径。实验继续检查当前模式的时钟、速度、暂停和显示；墙钟不代替游戏秒。仅凭整数顶栏时，必须给端点量化误差，不伪造浮点精度。

| 实验 | 唯一主要改变 | 对照和应核关系 | 不能由此推出 |
|---|---|---|---|
| E0 时间与显示 | 先稳定观察，再单独切速度／暂停 | 月界、游戏秒、UI净流与原生缓存；暂停不累计收入 | 全部模式速度／底层tick已相同 |
| E1 村民毛产 | 同一人采食↔已核等食耗的非粮任务 | 同P、无其他改变时，Food净流差应匹配失去／恢复毛产；施工材料单列 | 一次净余额斜率就是个人工资条 |
| E2 人口消费 | 普通人口P→P+1，新人转既有非粮岗 | 原粮工与修正固定，消费阶跃与`C(P+1)-C(P)`比较；多个P档复测 | 少数档位唯一识别全部C(P)及所有氏族 |
| E3 调岗 | 既有木工↔采食村民 | 总人口和同一伐木屋保留，分别看稳态资源向量和过渡人秒 | 木粮有永久固定兑换价或走路都停产 |
| E4 房屋／出生 | 一座房屋升级 | 人口／幸福等固定时比较容量与增长斜率，宽裕住房和封顶状态分层 | 一次出生间隔可分离所有幸福与growthBonus效应 |
| E5 知识与工具 | 分别单独学一项知识、完成一种工具 | 固定岗位；如要判加算／乘算，再做无／仅A／仅B／A+B四格 | 只做两个单开实验就确定叠加顺序 |
| E6 熊冬季 | 普通冬季边界；冬节另开对照 | 同P、岗位、其他效果，核Food冬罚、食耗、木耗；暴雪单列 | 全部资源统一乘一个冬季倍数 |
| E7 乌鸦转换 | 合法金币／粮食殖民或勘探岗位条件 | 同类地块和费用条件；支付、归属、施工、人员到岗分开；侦察知识看持续率与完成事件 | 把金币殖民当通用兑换，或把勘探知识当固定地块奖励 |

E4需同时记录升级的资源费用和维护，E5需记录锻造占人及完成时间。选择实验窗时不能用事后删样本掩盖不吻合：排除原因和原始窗口仍保留。

## 对账顺序

1. 先比较模型预测与原生毛产／消费，不用库存差冒充其中一项。
2. 再按原生缓存自身时钟积分，检查库存变化；费用、奖励、容量和消费触底另处理。
3. 错误、回退、身份切换、长缺口分别分段，暂停不能增加人秒。
4. 单人输入足够才比较该人的边际贡献；资料不足就返回区间／未知，不平均摊总量伪装逐人实产。
5. 条件不满足的结果保留为反例，回到代码分支查缺失输入。

## 官方脚本实验的边界

官方编辑器／脚本API可作为后续另立项的离线实验工具，先核安装随附API和版本。脚本或数据库修改、禁用出生／事件、人工给资源等会改变实验条件，必须使用独立、明确标记的自定义数据集；不得把结果混成未修改普通对局。当前优先用既有只读采集器与玩家正常操作做验证。

## 每条规则的验收记录

记录规则ID、版本双指纹、数学表达、输入来源、已知前提、排除／失败原因、对照与处理窗口、预测、观察、误差和未识别项。通过后只升级该规则在该条件下的证据等级；不把局部通过扩大为全部氏族或完整模拟器。
