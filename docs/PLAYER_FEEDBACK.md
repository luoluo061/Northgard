# 用一局经验改进人口、经济与出兵模型

我们想知道：同一名可调人口，在当时的氏族、知识、库存、月份和目标下，为什么用来采粮、伐木、出海、摸知识、施工、采矿或参战更有价值。熟练玩家的判断能解释“为什么这么做”，采集数据帮助检验“当时实际上发生了什么”。

3v3 中每人解释自己的选择；可以写本人理解的共同目标，例如准备同队集结或补某种资源。不要据此声称已经读到队友库存、聊天、命令或完整战术。各自的本人记录通过共享 UUID 与席位关联，缺少谁就保留缺失。

## 一条经验分四层写

反馈放入元数据的 `feedback` 数组，也可先使用 GitHub「玩家经验与反例」模板讨论。

1. **观察**：实际看到什么，发生在哪个时段。例如“第五名农民上岗时，住房已满”。未知数值不补写，采样时间不说成精确点击时间。
2. **推测**：你认为怎样解释。例如“粮食转正可能来自新增农民，也可能有临时加成，需要核对”。
3. **建议**：在什么目标和约束下会改变选择。例如“如果储粮仍够下一次集结，我会先留住房木材，再升级农田”。
4. **反例／条件**：什么情况会推翻建议，例如对方提前进攻、已有房屋工地、冬节已学、即将盛宴或需要马上殖民。

仅写“水手更好”“熊族应该五农”缺少时间、目标和适用条件；请说明原岗位放弃什么、多久能到新岗位、计划工作多久、建筑／转职花多少、下一项资源期限是什么。劳力比较不应把粮、木、金当作同一种等价单位。

## 用 A 年月、月段和游戏秒连接证据

`game_time_seconds` 是反馈连接采集的锚点，同时必须填 `time_precision`：

| 值 | 适用情况 |
|---|---|
| `exact_game_clock` | 确实记下原生游戏秒，而不是由墙钟猜测 |
| `sampled_interval` | 只能定位采样区间；观察文字中补充前后游戏秒 |
| `month_phase` | 只记得年月与月初／中／末 |
| `approximate` | 其他近似时间，需要说明依据 |

A800 年 3 月起点为 0；一个月 60 游戏秒，一年 720 秒。换算：

```text
游戏秒 = ((年份 - 800) × 12 + 月份 - 3) × 60 + 月内秒
```

月初／中／末是 `[0,20)`／`[20,40)`／`[40,60)` 的报告分组，不是游戏内部统一结算阶段。只记得月中时，先用约 30 秒寻找最近真实采集截面，再用其游戏秒锚定，并在文字中写“约”。反馈锚点应落在这份记录覆盖内；没有录到的开局可以在一般讨论中说明，不能伪造采集证据。暂停保持同一游戏秒，用记录顺序区分先后，不把等了多少墙钟秒当作劳动时间。

## 示例：为 3v3 出兵把农民转为水手

以下是格式示例，不代表项目已经验证了这条策略：

```json
{
  "game_time_seconds": 1710,
  "time_precision": "month_phase",
  "observation": "约 A802 年 7 月中，我把一名农民调去码头，具体指派和到岗时间以本人采集记录为准。",
  "hypothesis": "当时我认为凑齐下一次集结的克朗比增加储粮更迫切，但需要核对转岗期间损失的粮与临时加成。",
  "suggestion": "比较提前调岗与等粮食缓冲更充足再调岗，记录哪个方案能更早完成本人招兵目标。",
  "counterexample": "如果冬前粮已不足、马上要殖民或无法按时抵达集结，提前转水手可能更差；这不是所有氏族通用结论。",
  "confidence": "suspected",
  "unit_uids": []
}
```

`confidence` 可用 `observed`、`suspected`、`unverified`，分别表示主要在陈述观察、存在解释假设、经验尚待验证；这是贡献者自评，不是系统认证。单位 UID 不知道时填空数组。同一贡献里的 UID 可连接指派和职业，不能拿另一台电脑的相同 UID、鼠标选中顺序、位置或玩家名代替。

## 标签和多人连接写在哪里

顶层元数据填写自己的 `clan`、`mode`、`experience`、`goal`、`result`、`tags` 和 `feedback`。3v3 使用 `mode: "multiplayer"`；未知环境保留 null，胜负由实际结果填写，采集停止不等于获胜。

可用标签示例：`3v3试采`、`本人视角`、`人口分配`、`农民转水手`、`住房时机`、`出兵窗口`。标签用于检索，不证明这份数据已经完整验证。

`match_link` 单独保存本局参与者共用的 UUID、声明赛制、A／B 队伍和席位，不要把这些再塞进 `feedback` 充当额外协议字段。直接使用协作包生成的席位模板最容易保持一致；参见 [3v3 指南](MULTIPLAYER_3V3.md)。

## 公开分享前审阅

先停止采集、填标签和经验，再依 [贡献协议](DATA_CONTRIBUTION.md) 生成本地脱敏包。`consent_to_share` 默认 false，组织者生成模板不替玩家同意。只有本人已授权向这个公开仓库贡献这局时才提交；已有授权按范围继续，不重复确认例行步骤。

不提供姓名、Steam ID、聊天、联系方式、安装路径、凭证或其他玩家经济。现在的机器协议接收文字，不抓取或上传视频。自由文字仍要本人审阅；自动检查不能保证所有隐私都能识别。

多人贡献保留 `experimental_multiplayer_unverified`，尚未完成真实 3v3 短／整局验收。玩家经验、直接读数、模型推算和研究者归因分开保存。后续若验证某条机制，应保留原始观察、版本、反例与适用条件，而不把高手意见直接升级成通用规则。
