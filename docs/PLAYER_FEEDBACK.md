# 如何让一局经验帮助改进人口模型

我们希望知道：同一名可调人口，在当时的知识、氏族、库存和目标下，用来采粮、伐木、出海、摸知识、施工、采矿或参战，为什么可能更有价值。数量本身不够，目标和时机能解释决策。

请把每条反馈分为四层，写入元数据 `feedback`；也可以用 GitHub「玩家经验与反例」模板先讨论。

1. **观察**：实际看到什么。例：“A801 年 9 月中，我派第五名农民，指派后约十几秒才开始工作。住房已满。”没有确认的精确数值不要补写。
2. **推测**：可能怎样解释。例：“我认为主要延迟来自从矿区步行，另有缓存刷新；无法区分两者。”
3. **建议**：在什么条件下会做不同选择。例：“如果粮食还够过冬，我会先留木头出住房，再升级农田。”
4. **反例／条件**：什么情况会推翻建议。例：“有冬季消耗知识、即将宴会、对手进攻或已经有住房工地时，排序可能改变。”

`game_time_seconds` 是连接采集的时间锚点，必须同时填写 `time_precision`：`exact_game_clock`（确实记下原生游戏秒）、`sampled_interval`（只能定位采样区间）、`month_phase`（只记得月份阶段）、`approximate`（其他近似）。它不会自动成为精确指派时刻。

A800 年 3 月月初对应 0，A800 年 4 月对应 60。换算任意历法时间：`((年份 - 800) × 12 + 月份 - 3) × 60 + 月内秒`；月初／中／末只是 `0–<20`／`20–<40`／`40–<60` 秒。只记得月中时，以月内约 30 秒寻找最近真实采集截面，用它的游戏秒作为锚点，标记 `month_phase` 并在观察中写“约”。采集中途才开始时，不能把覆盖外的估计时刻硬塞进来。暂停仍停在同一游戏时间，用相邻记录序号区分先后。

```json
{
  "game_time_seconds": 1100,
  "time_precision": "month_phase",
  "observation": "A801 年 9 月中左右，第五名农民上岗；具体指派以采集器为准。",
  "hypothesis": "粮食转正可能来自新增农民，也可能有暂时加成，需核对知识和产量缓存。",
  "suggestion": "下局尝试更早规划住房，再比较同一月份的农田升级时机。",
  "counterexample": "如果已有住房工地、粮食不足或需要立即出兵，这条建议可能不适用。",
  "confidence": "suspected",
  "unit_uids": []
}
```

`confidence` 可填 `observed`（这一条描述主要是观察）、`suspected`（存在解释假设）、`unverified`（经验尚未验证）。它是贡献者自评，不是系统认证。单位 UID 可未知填空数组；不要拿名字、鼠标选中顺序或屏幕位置当持久身份。

比较两次安排时，可写当时目标（殖民下一块地／起港口／稳过冬／出熊／招军）、放弃旧岗位的产出、转岗固定成本、途中停产时长、工作持续多久、是否碰资源上限。说明哪些条件没有记录，比给一个无条件的“最佳开局”更有帮助。

不要提供其他玩家的姓名、聊天、Steam ID 或战绩链接。需要分享视频时另外确认视频里没有私人信息；当前机器协议只接收文字，不抓取或上传视频。讨论区中的建议经验证后应形成版本化机制证据，保留原始观察、反例和适用范围。
