# 从人口和库存，到真正可用的能力

这组转换卡回答“花掉资源、调走一个人，实际换到了什么”。阅读时同时保留**直接费用、占用劳力、等待、持续负担、形成的能力和失效条件**。资源不能仅按库存高低评价：侦察打开通路、熊清掉关键地、升级解除前置，都可能有价值，但要在需要的时候真正兑现。

本页对应[机读转换卡](../mechanics/catalog/conversions.v1.json)，核对日期2026-10-27，绑定`v4.3.29.43337 / Steam Build 25096976`及[规则登记](../mechanics/rules.v1.json)的hlboot/data.cdb双指纹。范围优先普通熊/乌鸦人类单人；征服、战役、编辑器、Bifrost、AI资源规则和多人经济预测不在这些卡的已核范围内。3v3可以借这些卡提出研究问题，不能直接继承单人模型、报价或出生门槛。

这些是核过配置和指定代码分支的能力转换卡；尚未给出完整经济模拟或最优打法。本页没有新增UI报价、付款或完成的实局回执，也不会把模型写入采集器的原生逐人实产字段。

## 费用要分成四种证据

| 口径 | 能说明什么 | 还缺什么 |
|---|---|---|
| 基础配置 | 当前表或普通常量向量规定的基础材料 | 当前模式、免费资格、折扣、死亡/重招等修正 |
| 条件报价推导 | 指定代码分支和完整条件下应返回什么 | 真实状态满足前提、当前原生报价观察 |
| 实际报价观察 | 某一时刻UI等原生来源显示的完整费用向量 | 玩家是否真的付款、操作是否成功 |
| 实际支付 | 已连接操作的付款记录，并与连续产消、其他支付和库存核对 | 项目是否完成、人员是否到位、能力是否已经生效 |

下面的基础费用都重新从本机指纹匹配的配置读取；普通武器/圣物的向量还核对了`Const.init #16591`中的组装位置。后续价格与付款入口分别审查。它们不是从旧攻略价格抄来的，也不是这次实付观察。

**英雄铁费存在待核冲突：本机配置是5铁，也有10铁的记忆，当前正常实局报价和支付尚未对上。** 5铁目前仅作为基础配置保留，不能据此确定本局招募预算。`getWarchiefCost #5022`还处理免费、招募、死亡/重招等状态；`hireHero #5031`依次检查、取报价、调用支付，再生成单位。后面的5铁／15铁组合都只是沿该基础配置的条件演算；英雄、可批量转职的盾兵、装甲熊是不同单位。

同样，“圣物需10铁”只说了一项材料；普通基础还要50木、100金，设施和劳动另计。英雄加这项圣物的基础铁预算为15铁，尚未包括其他工具或武器。精通盾牌只影响已核盾兵武器资源费，不能顺带免圣物或英雄费用。

## 现有人转岗，与增加一人是两种账

把同一个村民调去伐木，比较的是原粮食毛产损失、新木材毛产、过渡期、费用及消费差。如果已确认前后食耗相同，同一人的共同食耗在增量比较中抵消，不能再扣一遍。

```text
转岗的资源率变化
  = 新岗毛产 − 原岗毛产 −（新状态消费 − 原状态消费）
```

职业、指派和`produce`是输入证据；它们不是工资条。指派变化、走向建筑、任务改变、职业改变、候选生产恢复、玩家汇总率更新和库存到账要分开。采样只能给部分时刻的区间，不能把整段都称为纯走路；`Move`也不普遍等于停产。完整资格和加成缺失时，模型保留未知，详见[逐人产出边界](UNIT_PRODUCTION_LIMITS.md)。

新增一人则先要满足住房、幸福、进度和出生条件，之后才有能指派的劳动。食耗权重和等于住房P、难度和外层消费系数均为1、没有额外优惠/独立消费时，同质普通食耗的现有条件模型是：

```text
b(P) = 0.1 × (1 + sqrt(P / 46))
C(P) = P × b(P)
新增一名普通成员的全体食耗增量 = C(P+1) − C(P)
```

人口规模变化还会抬高原有成员的基础食耗，所以不能只记新人的个人食耗。上述简化要求食耗倍数和等于住房P；实际英雄、动物、军队/侦察优惠等仍要逐单位核资格。住房人口、实体数、取暖人数和有效劳力各有口径；兼容字段`population_cache`只是资源组件stored population，不能覆盖已核住房人口。

## 建筑下单以后，要一直追到投产

一条常见解释链是：

```text
合法下单/报价 → 支付 → 地基或项目创建 → 建造者接单、靠近与施工
  → 完成 → 生产指派 → 到岗/职业变化 → 满足生产资格
  → 玩家汇总率更新 → 按该资源的方式进入库存
```

这不是强制固定的点击顺序：工人可以提前指派，接近和施工阶段也可能重叠；采集器未必能分别观测每个时刻。重点是不要把“拍了建筑”“建筑完成”“工人到了”“实际产出”合成一个事件。

`startBuilding #4957`在已核普通路径先取`getBuildingCost #4935`的当前费用并支付；施工、完成、维护和生产是后面的环节。多工人施工曲线、调度与所有退款分支尚未闭合，故卡里没有填一个保证工期。比较方案时把原岗产出变化计入一次，避免又重复扣同一段“建造机会成本”。

殖民也应接到同一条链：发现机会、清除阻挡、合法支付、取得归属，然后才可能造设施和到岗。乌鸦金币殖民改变合法支付路径，不能当任意氏族固定粮金兑换；已拥有的地块也不能再次解释为新一笔殖民扣粮。未知地块内容、当前可通行性仍保留未知。

## “免费盾武”和“熊能清地”怎样形成不同能力

`getMilitaryUpgradeCost #13223 op9–39`对盾兵与有效精通盾牌的已核分支返回空资源向量；`Forge.startUpgradeUnit #13355`仍创建并启动锻造项目，`ForgeItem.get_forgeTotalTime #13405`仍走时间计算。省5铁50金与省设施、工人和时间不是同一件事。锻造在等工人或排队时，省下材料还没有自动变成军力。

Kaija的召唤路径不直接把一名已指派村民变成熊，但需要军事建筑入口及其材料、施工、维护和槽位。她打开哪块知识/粮/矿地，是清野投入的后续用途；远行、承伤和恢复也占用时间。鱼地粮流和恢复要求已核的同地块非海洋`Shoal`及能力/非交战等条件，不能把任意海岸当作生效。200声望地方生产的盾营与熊/英雄来源也不能重复叠加。细节和失败条件见[氏族战略案例](CLAN_STRATEGY_CASES.zh-CN.md)。

市政厅和侦察营两次基础升级合计150木、100金、15石；英雄另需基础5铁。这能解释某种矿物预算为何对应升级与英雄前置，但不能证明“挖完这些就能按时进攻”：还缺合法知识、工人、锻造、视野、行军、现金与过冬条件。若改做圣物或其他装备，预算就变了。

## 三类不能填零的缺口

| 转换 | 已有依据 | 卡里为什么保留未知 |
|---|---|---|
| 采矿劳动→石铁库存 | `#5855/#22437`共享进度与阈值提取路径 | 进度不是已入库矿物；多人、携带/离场、枯竭、余量等边界未全闭合，不给逐人到账或保证工期 |
| 知识库存→有效知识→岗位/能力 | `#13059/#13060/#13073/#13075/#13076/#13086/#13187`的指定前置/费用/获得路径 | 当前价格依赖类别、已有知识、模式与免费等状态；声望奖励不等于手点知识；储存条目不覆盖所有有效提供者 |
| 幸福/住房/进度→真实出生→有效劳力 | 已核普通熊/乌鸦单人FreeForAll的部分增长路径 | 完整`growthBonus`和出生门控未齐；到门槛不等于已出生；资源组件growth不替代市政厅进度 |

知识顺序要连到实际地图和期限：鱼叉需要鱼岗、冬节跑船需要海岸和有效水手，军线需要矿物、设施与能接敌的路线。同一知识在不同人口、季节、工人数和交战计划下会改变不同的能力；没有这些条件，卡片只列可行路径与缺口，不给统一顺序。

单人先自理清地、视野和生存；3v3还要知道队伍约定、谁清野、谁开图、共同接战时点。清地和视野的收益可能在队友后续行动上体现，不能仅用自己库存增长给它们打分。这里不会扩展读取他人经济。

## 如何拿这些卡做复盘与验证

以A年/月/月内阶段展示，底层一律用游戏秒。每次操作连接同一单位/建筑/地块身份，列出开始状态、费用证据、过渡阶段、完成/生效条件、资源向量变化和仍未解释的残差。先对毛产与消费，再按各自缓存时钟核库存；支付、奖励、上限溢出和离散提取单列。暂停不累计劳动，缺口、回退或身份变化必须断段。

还没有明确目标时，先比较同起点60/120/240游戏秒后能形成哪些库存与能力；形成实际目标后，再比较是否及时解除瓶颈、是否现金或粮食断档、挤掉了什么更急的行动。不要先设一个永久“1木换几粮”的分数，把全部机制压成总收益。

公开来源摘要：本轮私有离线校验重新确认六组基础费用，并在匹配字节码中核对15个费用/付款/项目相关函数锚点。普通武器向量组装位于`Const.init #16591 op730–754`，普通圣物位于`op755–788`；市政厅/侦察营价格入口为`Building.getUpgradeCost #5818`，圣物价格/支付为`#13225/#13235`。这些证据支持当前基础事实和指定流程，不代表所有修正、实际输入或实局实验已通过。完整配置、反汇编和本机校验回执留在本地，不进入公开卡。证据等级参见[机制证据](MECHANICS_EVIDENCE.md)，实际验收范围参见[验证状态](VALIDATION_STATUS.md)。
