# 先稳定记录，再完成每局复盘

当前优先级为稳定采集、质量核对和完整离线分析；实时战略提示与悬浮建议暂缓。既有实时系统研究保留作后续参考，不表示当前已有建议引擎。采集继续只读本人允许范围，游戏由玩家操作，记录默认留本机。

## 1. 怎样记录下一局

1. 使用现有Python，运行`python scripts/doctor.py`核对安装和规则。`ready_for_local_test`只代表准备就绪。
2. 为这一局选择新的输出目录：`python collector/collect.py --interval 0.5 --out-dir captures/新的一局`。省略`--seconds`才能持续录制；0.5是请求采样间隔，不是保证每帧耗时或无缺口。
3. 在已经授权记录的安排下，可以先启动采集器等待，再由玩家开局。确认第一帧的模式、氏族、人口、资源、游戏时间与分组件状态；没有采到的开头保留缺失。
4. 玩家正常玩，暂停不会累计生产、劳动和人口增长时间。长时间相同游戏时钟是时钟停滞证据，不能仅凭它断言某个暂停按钮状态。
5. 按Ctrl+C，或在本次目录创建`STOP`文件，等待manifest出现`recording_state=stopped`。不用强杀替代正常收尾；手动退出/停止不是胜负或自然终局。
6. 检查收尾与后处理，再生成本地复盘索引。另开一局优先另用目录；若同一目录已经记录多局，工具必须分别列出，不覆盖或串成一局。

网络断开、回菜单、游戏退出、采样拒绝、PID重连和游戏时间回退均保留记录。程序仍在运行不等于仍取得有效对局数据。尤其不能拿最后成功帧冒充现在，或为了让曲线连续而用上一帧填满缺口。

## 2. 每次停止后先做质量检查

```powershell
python scripts/summarize_capture.py --capture captures/新的一局
python scripts/summarize_capture.py --capture captures/新的一局 --out .local/这一局-review.json
```

该命令默认只处理已停止的录制，流式读取本地文件，输出本地事实索引；现有目标文件不覆盖，不联网、不启动采集、不替代贡献审阅。JSON是后续完整分析的输入，不是已经得到最优打法的报告。

| 检查 | 必须保留的结果 |
|---|---|
| 身份 | session_key、capture_run_id、capture_segment_id分组；不能只按A年/月或地块UID连接 |
| 覆盖 | 第一/最后观测时刻、有效行、独立游戏时刻、各组正向间隔与回退、是否观察到结束 |
| 暂停与失败 | 相同游戏时钟不当作额外劳动；health失败单列，退出后的等待错误不直接算作局内缺失时间 |
| 文件与字段 | 实际打开数据流；目录中的文件大小可能暂未更新，不能仅据0字节判空；缺字段/坏行/缺身份显式报告 |
| 组件 | 资源、劳动、增长、地图、付款等分别检查；partial不使未知变零，也不代表全部数据不能使用 |
| 后处理 | stopped与对账结果分开。0.5.3先保存stopped/pending；对账失败留下安全诊断，原始记录不改写 |

跨run即使同属一个session也不跨边界积分。后续若要关联读档或进程重启前后的同一比赛，需要另外的身份依据；不会自动把不同session拼起来。

## 3. 完整复盘的固定内容

展示按A年、月份及月初/中/末；底层保持实际游戏秒和事件区间，不把每月看成统一结算点。

| 分析部分 | 必须回答的问题 |
|---|---|
| 开始条件 | 第一帧是什么模式、氏族、资源、人口与已知地图；是否缺少真正开局 |
| 人口与岗位 | 何时出生、卡容量、调岗、施工、侦察、采矿或转军；实际任务与职业标签分别看 |
| 殖民与地图 | 当时已知哪些候选、有什么资源与阻挡、花了多少、取得后怎样使用；不拿后来的地图补过去 |
| 建造与升级 | 开工付款、施工占人、完成、派工、有效工作分别连接；完工事件不是扣材料时点 |
| 知识、声望与临时效果 | 实际学习/生效时间、前置与下一步用途，尤其核对先学优惠还是先付款；点数、解锁等级和配置参考分开 |
| 资源账 | 粮木金产消、库存、一次性支付/收入、上限、矿物离散到账、未解释残差与覆盖区间 |
| 阶段节奏 | 住房、首冬、宴会、殖民、采矿、升本和军力是否相互配套，何处出现等待或材料错配 |
| 改进与反事实 | 从当时可知状态比较少量可行替代；明确所需条件、估计误差和可能失效的情况 |
| 结果与边界 | 是自然终局、主动退出还是只录到某月；哪些判断可靠，哪些因数据不足只能列假说 |

一项结论同时列事实、解释与待验证部分。例如原生付款能支持“这笔粮用于殖民”，却不能单独证明“换个殖民顺序必胜”。持续采矿与低粮相邻，也要核对同一时段的建造、人口和一次性付款，不能把全部粮食下降归给矿工。

遗迹/宝藏的取得、探索开始、完成与领奖分别处理；当作自有对象后才读取到的内容，不能伪装成此前已经观测。原生事件可保留历史发生时间，但当时的库存、人员与地图状态没有采到时仍然缺失。

## 4. “完整”怎样判断

完整分析意味着对实际记录范围逐段交代，并尽量解释每个重要选择及资源变化；不意味着已经得到每个鼠标点击、逐人原生最终收入或所有动态机制。状态采样有时间分辨率，同一间隔内多个动作可能无法唯一归因。

第一批验收以玩家正常操作的熊族普通单人完整窗口为主，核对开局、暂停、调岗、人口封顶与恢复、一次殖民/建造/知识/矿物到账、退出和停止。3v3保留实验状态，按各人本人视角独立验证。已有截断记录可以完整分析已录部分，但不能冒称整局或A800–A802全覆盖。

原始数据、私人复盘和读前缀/文件哈希都保留本机；公开上传仍按该局独立授权及[贡献流程](DATA_CONTRIBUTION.md)。代码与泛化文档可维护到仓库，玩家实际对局不随之发布。
